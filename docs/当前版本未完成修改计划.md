# 当前版本未完成修改计划

## 核对依据

- 主结构：`中煤 AI 创新应用平台 · 产品功能需求全景.xmind`
- 细节补充：`中煤客户反馈需求文档_会议手工梳理合并版_V1.3.md`
- 核对对象：当前 Vue 演示版本

执行规则：两份材料冲突时以最新 XMind 为准；账号、角色、数据权限、指标口径和系统管理细节由会议文档补充。本文只列当前未完成、实现不足或需要重新确认的内容，已经符合要求的功能不重复列入。

## 1. 全局规则、账号与权限

- [ ] 全站继续清理面向客户的“Agent”字样，统一为“智能应用”；仅在技术配置、模型说明等确有必要的位置使用 Agent。
- [ ] 登录页补齐真实产品状态：账号密码登录、企业单点登录、记住登录状态三种能力需要分别说明接入条件和失败反馈，不能把演示点击效果当成已接通服务。
- [ ] 明确三类使用者的页面权限：科研人员、复核/裁判人员、平台管理员；各角色只能看到职责范围内的入口、数据和操作。
- [ ] 个人中心改为只读账号信息：工号、姓名、公司、部门、角色由管理员或主数据系统维护，普通用户不能自行修改。
- [ ] 个人知识库、历史记录、管理员工作台与驾驶舱的入口继续按角色收敛，避免同一功能在多个位置重复出现。
- [ ] 对按钮和关键操作补齐统一交互契约：可点击条件、点击后的页面或状态、失败反馈、完成后的保存结果。
- [ ] 所有演示数据统一标明“演示数据”或“待接接口”，不把静态数据描述成真实生产数据。

## 2. 语义检索

- [ ] 输入区加入完整的新手示例，示例文本满足会议要求的输入完整度，并可一键带入输入框。
- [ ] 检索前补齐必要条件：检索主题、应用场景、关注指标、排除范围；输入不足时给出明确提示。
- [ ] 对专利、论文、政策法规、企业知识库、个人知识库分别说明数据来源、可用状态和服务异常时的降级方式。
- [ ] 结果列表进一步统一字段：名称、来源、公开/更新时间、相关度、排序依据、资料类型及可用状态。
- [ ] 详情页补齐原文定位、关键段落或附图查看；不能只有摘要卡片。
- [ ] 专利或外部检索服务暂停时，页面应保留已有结果并明确说明受影响范围，不能给出完整检索已完成的误导结论。

## 3. 技术问答

- [ ] 引用标记需要与回答中的具体判断逐句对应，不只在回答底部集中列来源。
- [ ] 引用支持悬停查看资料摘要、来源与日期，点击后再进入完整详情。
- [ ] 企业知识库与个人知识库作为两条独立召回通道显示在来源说明中，并说明当前回答实际采用了哪一路资料。
- [ ] 当来源不足、外部服务不可用或不同资料相互冲突时，回答中必须给出可见提示和待核验项。
- [ ] 继续压缩与连续问答无关的流程说明，使页面保持接近常用对话工具的直接交互。

## 4. 技术预研报告

- [ ] 输入信息需要与补充要求真正合并进入同一任务上下文，页面要能查看本次报告采用了哪些补充内容。
- [ ] 完整报告补齐 XMind 中约定的全部章节，当前示例正文不能只展示少量章节。
- [ ] 报告目录需要支持真实章节跳转和当前章节高亮。
- [ ] 报告中的结论、数据和引用需要打开来源详情并定位到引用内容。
- [ ] Word 下载从演示提示升级为真实可下载文件；后续接后端时保留报告版本、任务编号和生成时间。
- [ ] 明确大纲确认、返回修改、补充要求和重新生成之间的数据保留规则。

## 5. 创新性分析（科研人员端与管理员/裁判端）

### 5.1 两类智能应用的角色差异

- [ ] 科研人员端按“不完整方案输入”设计：允许先输入技术构想，再逐步补齐缺失项；不显示评分、等级和裁判规则。
- [ ] 管理员/裁判端按“完整方案输入”设计：提交前检查必填信息，缺失字段必须补齐；可查看评分规则、权重、等级和完整评价依据。
- [ ] 两端在入口名称、页面说明和最终报告内容上清晰区分，不能只依赖一个角色标签切换同一套页面。

### 5.2 信息确认与证据管理

- [ ] 项目信息确认页补齐 XMind 规定字段，并标明系统提取值、用户补充值与待确认值。
- [ ] 每一步返回后保留本步骤数据；修改后只能形成当前版本，不恢复已经被替换的旧输入版本。
- [ ] 技术主题与创新点分别检索，建立一个创新点对应多条证据、同一证据支持多个创新点的关系。
- [ ] Top 100 证据池补齐分页或分段浏览，不以少量卡片代替完整候选集。
- [ ] 补充检索支持勾选加入、自动去重、删除和重新排序；证据变化后相关结论需要重新计算。
- [ ] 专利、论文、政策法规、企业知识库、个人知识库统一显示来源标识、语义相关度、日期和原文定位。
- [ ] 证据悬停预览资料详情，点击后查看完整内容和引用位置。

### 5.3 权重、评价与报告

- [ ] 管理员在生成报告前选择管理员维护的权重模板，并保存本次采用的模板版本。
- [ ] 管理员报告补齐 A/B/C/D 等级、各创新点评价和客观理由；不输出投资建议、否决性结论或越权决策。
- [ ] 科研人员报告只展示创新判断、证据、风险和改进建议，不展示分数、权重或裁判等级。
- [ ] 报告增加可编辑与确认流程，明确显示 1/3、2/3、3/3 当前步骤和确认结果。
- [ ] 报告支持目录跳转、网页全屏、Word/PDF 导出，并记录报告人、账号、生成日期和版本。

## 6. 可行性分析

- [ ] 论文召回需要显示介入到哪一个分析步骤、哪些论文被选中以及对应支持或反驳的判断。
- [ ] 企业知识库与个人知识库两路召回分别展示来源和排序规则。
- [ ] 风险、约束、缺陷、验证路径与引用证据建立可点击关系，避免只展示孤立结论。
- [ ] 完整报告补齐目录、来源详情、导出和版本信息。
- [ ] 当输入方案缺少工程边界或验证指标时，先要求补充，不能直接给出完整可行性结论。

## 7. 技术交底书撰写

- [ ] 生成前增加结构化缺项检查，分别确认技术问题、技术方案、有益效果、实施方式和附图资料。
- [ ] 当前“专利服务暂停”提示继续保留，并将受影响章节和后续补充方式写清楚。
- [ ] 输出页的正文与重点内容建立联动，点击重点可定位到对应段落。
- [ ] 导出的交底书需要包含任务编号、版本、资料来源和待研发人员确认项。

## 8. 历史记录

- [ ] 按最新 XMind 补齐排序、批量选择、删除和全部删除操作，并设置删除确认和恢复范围。
- [ ] 点击历史任务后应回到上次停留步骤，而不是一律打开最终成果。
- [ ] 历史记录保存输入快照、步骤状态、已选证据、报告版本和使用的智能应用。
- [ ] 重新生成时覆盖当前任务的最新结果，不额外制造多条无法区分的历史记录。
- [ ] 页面结构继续向会议确认的 Eureka 历史中心靠齐，具体视觉与字段在该页面修改前单独确认。

## 9. 个人中心与个人知识库

- [ ] 删除普通用户编辑昵称、职务、手机和邮箱的能力，改为只读主数据。
- [ ] 个人知识库明确“仅本人可见”，并显示哪些智能应用允许召回。
- [ ] 文件列表补齐来源、更新时间、解析状态、排序规则和检索状态。
- [ ] 创建、编辑、上传、删除、回收站和恢复操作接入持久化数据；当前仅前端演示的操作不能视为真实保存。

## 10. 管理员工作台

### 10.1 用户、组织与角色

- [ ] Excel 批量导入补齐模板下载、必填字段校验、成功/失败数量和失败原因下载。
- [ ] 单独创建用户时区分账号、工号、姓名、公司、部门、角色、状态和智能应用权限。
- [ ] 公司与部门层级从 OA/主数据系统同步，管理员只做校验和授权，不在多个页面重复维护组织结构。
- [ ] 增加独立角色管理：角色定义、数据范围、六项智能应用权限和管理功能权限。
- [ ] 管理员、裁判人员、科研人员的功能权限和数据权限分别配置。

### 10.2 知识库、模板与配置

- [ ] 公司知识库补齐公司/部门/子部门使用范围、资料来源、文件管理、回收站和召回权限。
- [ ] 评分权重模板支持新建、版本、启停、应用范围和历史使用记录。
- [ ] 智能应用配置补齐各数据源召回上限、服务可用状态和降级策略。
- [ ] 模型配置只展示管理员需要的服务状态和可替换项，密钥不得出现在前端。

### 10.3 运营与审计

- [ ] 运营统计按登录、任务发起、检索、完成、报告生成、失败、复核等事件记录，不使用无法说明来源的模拟进度。
- [ ] 任务完成度统一为 0/1；调用成功率明确分子、分母和不纳入统计的情况。
- [ ] 审计日志补齐用户、时间、智能应用、动作、结果以及对外调用的专利/论文标识。
- [ ] 操作记录支持按时间、用户、公司、部门、角色和智能应用筛选排序。

## 11. 管理员驾驶舱

- [ ] 保持深色、克制的总览风格；功能结构按最新 XMind 补齐日期和公司筛选。
- [ ] 补齐整体调用量、任务完成率、平均响应时长、平均活跃度、平均使用频次、调用成功率，并为每项提供数据来源与计算口径。
- [ ] 增加任务状态 0/1 分布和六项智能应用表现对比。
- [ ] 增加集团、二级公司、部门使用情况对比，并按管理员数据范围控制可见公司。
- [ ] 区分任务发起次数、智能应用调用次数、成果/报告数量和复核数量，不能混为同一指标。
- [ ] 区分系统处理时长与人工处理时长；尚未接后端的指标明确标记为演示数据。
- [ ] XMind 要求的筛选与查看能力优先于会议文档中的“静态无交互”描述；具体交互形式在驾驶舱修改前单独确认。

## 12. 后端接入与生产约束

- [ ] 账号、组织、用户、权限、知识库、任务、证据、报告和日志全部定义接口与持久化模型。
- [ ] 专利、论文、政策、企业知识库和个人知识库支持数据源替换、可用性检测和局部降级。
- [ ] SSO、OA 组织同步、Excel 导入、文件解析、Word/PDF 导出和原文跳转接入真实服务。
- [ ] 对外访问建立域名白名单，记录访问对象和失败原因。
- [ ] 模型替换后执行检索、引用、报告结构、权限隔离和性能回归验证。
- [ ] 补齐接口、部署、运维、权限、日志和异常处理文档。
