# 权限架构与前后端接口约定

> 状态：前端 Demo 的实现约定。当前判断基于本地演示数据，不代表已经接入服务端鉴权。

## 1. 当前角色

| 角色代码 | 展示名称 | 当前能力 |
| --- | --- | --- |
| `user` | 普通用户 | 使用智能应用；在所属部门落入资料库可见范围时，可查看和使用资料库内容。 |
| `admin` | 管理员 | 可进入管理中心；在所属部门落入资料库可见范围时，可查看、上传、编辑资料库。 |

高级管理员暂不在 Demo 中单列。后续仅增加“任命或撤销普通管理员”的能力；资料库范围规则保持一致。

## 2. 用户与组织字段

```ts
type User = {
  id: string
  account?: string
  role: 'user' | 'admin'
  departmentId: string
  department: string // 仅展示
  company: string // 仅展示
  status: '启用' | '停用'
}

type OrganizationUnit = {
  id: string
  parentId?: string
  name: string
}
```

`departmentId` 是权限判断唯一使用的组织标识；部门名称可以调整，不应改变用户的数据范围。每位用户都必须对应组织树中的一个部门 ID，前端不提供“未分配部门”状态。

## 3. 公司资料库范围

```ts
type Visibility = {
  mode: 'group' | 'department' | 'department-children' | 'custom'
  ownerDepartmentId: string
  departmentIds: string[]
}
```

| 范围模式 | 部门匹配规则 |
| --- | --- |
| `group` | 全集团已分配部门均在范围内。 |
| `department` | 仅 `ownerDepartmentId` 对应部门。 |
| `department-children` | `ownerDepartmentId` 及其所有下级部门。 |
| `custom` | `departmentIds` 中每个部门及其所有下级部门。 |

统一规则：部门在可见范围内的普通用户可查看或使用资料库；同一范围内的管理员可编辑。范围外的管理员不显示该资料库，也不能通过前端交互打开它。

## 4. 前端策略入口

`src/services/accessPolicy.js` 是当前 Demo 的唯一策略入口：

- `isManagementAdmin(profile)`：管理中心入口能力。
- `isResourceVisibleToDepartment(...)`：部门是否落入资源范围。
- `canViewCompanyLibrary(...)`：资料库查看能力。
- `canEditCompanyLibrary(...)`：管理员且资料库范围匹配时的编辑能力。

页面不得重复拼接范围判断。管理中心路由使用管理员能力拦截；资料库目录和打开操作使用同一范围策略。

## 5. 后端接入要求

后端须以登录凭证中的用户身份为准，不能信任前端提交的 `role`、`departmentId` 或范围判断结果。每次读取、上传、编辑、删除资料库内容，都应在服务端执行：

```text
用户状态为启用
→ 读取用户角色与 departmentId
→ 读取资源 visibility
→ 判断部门是否命中范围
→ 判断操作是否要求 admin
→ 允许或拒绝
```

建议接口返回当前用户的 `id`、`role`、`departmentId` 和组织信息；资料库返回完整 `visibility`。前端只负责展示、交互预拦截和空状态，后端是最终授权依据。
